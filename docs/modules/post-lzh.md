# 廖子豪的印记后端交付说明

本分支 `feat/posts-lzh` 基于 `develop` 的 `e820f8a`，实现发布、首页列表和详情，接口契约已写入 [docs/api.md](../api.md#印记发布首页与详情)。目前状态为可联调，团队环境待验收。

## 实现与代码位置

代码位于 `backend/src/main/java/com/momentsync/post/`。

| 文件 | 职责 |
| --- | --- |
| `PostController.java` | 提供 `POST /api/posts`、`GET /api/posts`、`GET /api/posts/{id}` |
| `CreatePostRequest.java` | 校验字段类型与长度、图片引用、字符串标签 ID，规范化可选字段 |
| `PostService.java` | 使用当前登录身份，检查标题和正文敏感词，在事务中保存完整印记 |
| `PostRepository.java` | 扩展既有仓库，复用搜索的响应组装、公开规则和标签加载，保存图片及标签关联 |

首页复用现有搜索查询，详情复用同一响应字段与 `PUBLIC + PUBLISHED` 规则。发表评论后，详情查询只统计 `PUBLISHED` 评论。发布时标签有效性检查、印记写入、图片关联与标签关联共用事务。

## 测试复现

仓库根目录执行下面的命令。

```bash
mvn -f backend/pom.xml clean verify
node --test miniprogram/tests/*.test.cjs miniprogram/modules/post/tests/*.test.cjs miniprogram/modules/search-comment/tests/*.test.cjs
```

印记测试默认使用 H2。验证 MySQL 8 时，准备独立的 `moment_post_test_*` 测试数据库，设置 `POST_TEST_DB_URL`、`POST_TEST_DB_USER`、`POST_TEST_DB_PASSWORD`，运行 `mvn -f backend/pom.xml -Dtest=PostIntegrationTest test`。测试会重建和清空该测试库内的业务数据。

## 团队验收顺序

1. 普通用户登录，选择真实标签、心情、地点，通过上传接口得到图片引用。
2. 发布印记，确认响应带字符串 `id`，刷新首页后进入对应详情。
3. 核对作者、图片、标签、心情、地点和正文。搜索该印记，发表评论，详情刷新后评论数增加。
4. 分别在标题、正文输入演示敏感词，验证 `422 / 42201` 与页面提示。非法标签或参数返回 `400 / 40001`。
5. 管理员通过后台下架同一条印记。普通用户刷新首页、搜索后不再看到它，使用原 ID 访问详情、读取或发表评论都返回 `404 / 40401`。
6. 验证登录失效与空列表状态，记录缺陷并回归，验收后由团队集成稳定版本。
