# 拾光同频第一周分工方案

## 1. 本周目标

本周采用轻量 Agile 模式协作，完成一个可以稳定运行和演示的基础 Demo。

核心业务流程为：

```text
用户登录 → 发布印记 → 首页查看 → 搜索内容 → 发表评论
                              ↓
                    管理后台查看并下架
```

现阶段先确定前端、后端和任务管理等抽象职责。具体功能任务在前后端项目骨架和接口规范确定后，再根据工作量和依赖关系进行分配。

## 4. 前端本周内容

由段晨鸣负责组织，吉虹颖、郑凯柔和江可妮参与开发。

- 搭建微信小程序基础工程。
- 确定前端目录、公共样式和组件规范。
- 封装网络请求和登录状态处理。
- 完成用户登录页面。
- 完成首页印记列表。
- 完成印记发布和图片选择页面。
- 完成印记详情页面。
- 完成关键词或标签搜索页面。
- 完成评论展示和发表评论功能。
- 对接后端真实接口。
- 处理加载、空数据、请求失败和登录失效状态。
- 统一页面样式并完成前端自测。

前端负责人先搭建公共基础，具体页面和组件任务再由成员领取。

- 连接 MySQL 数据库。

- 实现图片上传接口。
- 实现印记发布、列表和详情接口。
- 实现关键词和标签搜索接口。
- 实现评论发布和查询接口。
- 实现管理员登录、用户查询和内容查询接口。

- 编写必要的单元测试和接口测试。

后端负责人先搭建工程骨架和公共能力，具体接口和业务任务再由成员领取。

## 6. 其他本周内容

由吉虹颖负责协调，全体成员共同参与。

- 确定本周 Demo 的功能范围和验收标准。
- 将需求拆分成可以领取和验收的开发任务。
- 建立并维护任务看板。
- 确定任务优先级和依赖关系。
- 由前端负责人和后端负责人共同确定接口输入输出。
- 维护接口文档和数据库脚本。
- 准备管理员账号、普通用户账号和演示数据。
- 组织对应前端和后端成员进行联调。
- 记录并修复开发过程中发现的问题。
- 更新 README 和项目启动说明。
- 准备固定的 Demo 演示流程。
- 将经过联调和验收的稳定版本合并到 `main` 分支。

## 7. 任务分配流程

1. 吉虹颖确定本周范围并整理用户故事。
2. 段晨鸣完成前端骨架和公共规范。
3. 周黎完成后端骨架和公共规范。
4. 前端负责人和后端负责人共同确定核心接口。
5. 吉虹颖将需求拆成具体任务，标注优先级、依赖和验收标准。
6. 成员根据所属方向和当前工作量领取任务。
7. 开发者完成代码和自测后提交合并请求。
8. 前端或后端负责人审核代码。
9. 对应前端和后端开发者共同完成联调。
10. 吉虹颖按照验收标准确认任务完成。

## 8. 协作原则

- 具体任务确定后，每项任务应有一名主要负责人。
- 前端统一遵循段晨鸣制定的目录、组件和样式规范。
- 后端统一遵循周黎制定的分层、接口和数据规范。
- 接口发生变化时，必须同步通知相关成员并更新接口文档。
- 谁开发谁自测，相关成员进行交叉验收。
- 涉及前后端的功能必须使用真实接口完成联调后，才能标记为完成。
- 日常开发提交到个人功能分支，再合并到 `develop`。
- 经过联调和验收的稳定版本才能合并到 `main`。

## 9. 本周暂不完成

- 视频发布。
- 好友和圈子系统。
- 即时聊天。
- 时光胶囊和故事集。
- 复杂同频推荐。
- 大模型 Agent。
- 正式服务器部署。
- 专职测试、运维或文档岗位。

## 10. 本周完成标准

- 微信小程序、Spring Boot 后端和 MySQL 可以正常运行。
- 普通用户和管理员能够登录。
- 用户能够发布、查看、搜索和评论印记。
- 管理员能够查看并下架内容。
- 下架后的内容不会继续在小程序公开列表中显示。
- 接口文档与实际代码保持一致。
- 核心功能完成自测和前后端联调。
- README、演示账号、演示数据和演示流程准备完成。
- `main` 分支中保存可以稳定演示的版本。
